Local Memory System 使用说明

本地记忆系统：从资料导入到任务上下文

这份说明面向第一次使用者，帮助你在本机启动系统、创建资料库、导入资料、检索来源、保存上下文，并理解模型处理和数据边界。

系统定位 安装启动 使用流程 资料库结构 模型处理 CLI 命令 边界与安全 常见问题

1. 系统定位

本地记忆系统用于长期项目中的 AI 协作记忆管理。它不追求让助手无差别记住所有内容，而是把资料、来源、版本、人工纠正、加工知识和任务上下文分开保存，让每次调用 AI 前都能知道“这次引用了哪些资料”。

适合的场景

  • 长期项目资料整理和复用。
  • 商务、产品、研发、交付、运营等需要来源依据的工作。
  • 为 ChatGPT、Codex 或其他助手准备有边界的任务上下文。
  • 本地优先的个人或团队知识库试用。

不适合直接承诺的能力

  • 不是自动采集所有聊天历史的工具。
  • 不是多用户权限系统或企业级安全网关。
  • 不是无条件自治代理。
  • 默认字面检索，不等同于语义搜索。

2. 安装与启动

运行环境建议使用 macOS 或类 POSIX 环境，Python 3.9 及以上版本。系统运行不需要数据库服务，索引使用本机 SQLite 重建。

从 GitHub 获取代码

git clone git@github.com:pzhcyh/local-memory-system.git
cd local-memory-system

启动默认本地服务

./start.command

启动后打开：

http://127.0.0.1:4191/

默认启动会在仓库内创建两个本地目录：

  • .local-data/：保存演示库和空库的数据。
  • .local-state/：保存模型配置、队列和服务运行状态。

这两个目录默认被 Git 忽略，不会提交到仓库。

只启动基础文件库

./start-m1.command

后台启动与停止

./start-background.command
./stop-background.command
说明：后台控制脚本只管理自己登记过的服务进程。端口已被其他进程占用时，它不会接管或停止对方进程。

指定自己的资料库

python3 -m memory_service.server --init --port 4191 \
  --vault "work=/absolute/path/to/your/vault"

3. Web 页面使用流程

  1. 打开 http://127.0.0.1:4191/。
  2. 在页面顶部选择一个资料库，例如 demo 或 empty。
  3. 进入“导入资料”，填写项目名、来源 ID、文件名和资料内容。
  4. 保存后进入“原始资料”或“项目检索”，按项目查看和检索。
  5. 如果该项目已有加工知识，进入“任务上下文”区域，输入本次任务问题和字节预算。
  6. 点击准备上下文，核对引用来源、版本和内容。
  7. 确认后保存上下文文件，把生成的 context.md 交给 AI 助手读取。

导入资料时建议填写

字段建议
项目名使用稳定名称，例如客户名、项目名、专题名。
来源 ID同一来源后续更新保持相同 ID，不同来源使用不同 ID。
文件名保留可读后缀，例如 meeting-note.md、orders.csv。
内容只导入当前允许保存的材料，不导入密钥、密码或未经授权资料。

任务上下文怎么用

任务上下文是一次任务的“引用快照”。它会记录项目、查询、知识版本、来源路径、引用行号和引用内容。保存后的上下文不会自动更新；如果来源或当前知识变化，系统会标记旧上下文已过期。

注意：上下文命中依赖当前加工知识。没有命中不代表原始资料里没有答案，也不代表业务事实不存在。

4. 资料库结构

资料库是普通文件夹，可以脱离服务直接查看。核心结构如下：

vault.json
INDEX.md
originals/
knowledge/
  projects/
  contexts/
  source-evidence/
.staging/
路径用途
vault.json资料库身份和 schema 信息。
INDEX.md可直接阅读的入口索引，可由服务重建。
originals/保存原始资料的不可变版本。
knowledge/projects/保存按项目生成的加工知识和当前入口。
knowledge/contexts/保存任务上下文快照。
knowledge/source-evidence/保存 CSV 来源证据包。
.staging/原子写入暂存区，异常时用于保留现场。

5. 模型处理与人工纠正

模型处理是可选能力。配置模型并不等于允许模型处理所有资料；真实资料应按具体项目保存授权后再进入处理队列。

建议流程

  1. 进入“模型服务”，添加模型连接。
  2. 完成固定能力检查。
  3. 为具体资料库、项目、模型版本和处理策略保存授权。
  4. 进入“记忆管家”，把该项目加入队列。
  5. 运行有限一轮，完成后核对加工知识来源。

人工纠正

当加工知识不准确时，不要直接覆盖原始资料。应在页面中选择对应知识条目进行纠正。纠正会作为新的来源记录保存，旧知识标记为待复核，重新处理后才会形成新的当前知识。

6. CLI 常用命令

CLI 默认连接 http://127.0.0.1:4191。服务运行后可执行：

python3 memoryctl.py --vault demo status
python3 memoryctl.py --vault demo list
python3 memoryctl.py --vault demo search --project "Example" --query "keyword"
python3 memoryctl.py --vault demo context --project "Example" --query "what should I know?" --max-bytes 4096
python3 memoryctl.py --vault demo contexts --project "Example"

提交资料

提交资料需要准备完整 JSON 文件，并使用新的 eventId。不要重复使用别人的验收样本事件。

python3 memoryctl.py --vault demo submit payload.json

CSV 来源证据

python3 memoryctl.py --vault demo csv-search --project "Example" --query "第二行"
python3 memoryctl.py --vault demo csv-evidence --project "Example" --query "第二行" --max-bytes 8192
python3 memoryctl.py --vault demo csv-evidence-list --project "Example"

7. 数据边界与安全

  • Web 服务只绑定 127.0.0.1。
  • 页面按文本显示导入材料，不执行其中的 HTML 或脚本。
  • 浏览器令牌只保存在内存中，是本机会话保护，不是多用户认证系统。
  • 来源校验值用于完整性检查，不等于带密钥签名。
  • 默认发布仓库不包含私有数据、运行状态、模型凭据或个人资料库。
  • 同一系统用户下的其他本机进程仍属于当前信任边界内，不能把本系统当作抵御本机用户的安全沙箱。

8. 常见问题

页面打不开

先确认服务是否启动，并检查端口是否被占用：

python3 scripts/service_control.py status

提示端口已有监听

说明 4191 已被其他进程占用。后台控制脚本不会接管未知进程。可以停止自己的旧服务，或换一个端口直接启动。

上下文显示过期

说明来源、知识版本或知识状态发生变化。请重新准备上下文，再保存新的快照。

模型未配置或未授权

这不是故障。文件导入、原始检索和部分上下文能力仍可使用。需要模型处理时，再按项目授权。

如何确认没有把本地数据提交到 Git

git status --short
git check-ignore .local-data .local-state evidence

如果这些目录被 Git 忽略，说明默认开源边界仍然有效。

English Summary

Local Memory System is a local-first project memory workbench for AI-assisted work. It keeps source files readable as ordinary local files, preserves immutable versions, separates raw sources from derived knowledge and saved task contexts, and requires explicit project-level authorization before model processing of real material.

Start it with ./start.command, open http://127.0.0.1:4191/, import project material, search sources, prepare a bounded task context, and hand the saved context.md to an AI assistant when needed.
